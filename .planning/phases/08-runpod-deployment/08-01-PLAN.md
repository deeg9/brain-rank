Create two files:

**scripts/build_and_push.sh** -- Bash script that:
1. Sets strict mode (set -euo pipefail)
2. Accepts DOCKER_USERNAME and IMAGE_NAME as env vars (defaults: IMAGE_NAME=neurocut-worker)
3. Requires DOCKER_USERNAME to be set (exit with message if not)
4. Requires HF_TOKEN to be set (exit with message if not -- needed as build arg for gated model access)
5. Builds with: `docker build --platform linux/amd64 --build-arg HF_TOKEN="$HF_TOKEN" -t "$DOCKER_USERNAME/$IMAGE_NAME:latest" .`
6. The --platform linux/amd64 flag is CRITICAL -- user is on macOS ARM64 but RunPod runs linux/amd64
7. Pushes with: `docker push "$DOCKER_USERNAME/$IMAGE_NAME:latest"`
8. Prints the full image URL at the end for copy-pasting into RunPod
9. Add a comment at top: "Run `docker login` first if not already authenticated"
10. Estimated build time: 15-30 minutes (large ML dependencies)

**scripts/test_endpoint.py** -- Python script that:
1. Reads RUNPOD_API_KEY and RUNPOD_ENDPOINT_ID from environment variables
2. Exits with clear message if either is missing
3. Accepts an optional video URL as CLI argument (default: Sintel trailer from Phase 1/3 testing -- use "https://download.blender.org/demo/movies/Sintel.2010.720p.mkv" or a shorter clip URL)
4. Submits job via POST to `https://api.runpod.ai/v2/{endpoint_id}/run` with JSON body `{"input": {"video_url": video_url}}`
5. Headers: `{"Authorization": "Bearer {api_key}", "Content-Type": "application/json"}`
6. Polls GET `https://api.runpod.ai/v2/{endpoint_id}/status/{job_id}` every 30 seconds
7. Prints status on each poll (IN_QUEUE, IN_PROGRESS, COMPLETED, FAILED)
8. On COMPLETED: pretty-prints the output JSON and saves to `data/endpoint_test_result.json`
9. On FAILED: prints the error and exits with code 1
10. Timeout after 25 minutes (1500 seconds) with clear message
11. Uses only stdlib (requests is fine -- it's in the project already, but prefer urllib.request for zero-dep script) -- actually use requests since it's simpler and the user has it
12. Import sys, os, time, json, requests

Both scripts should have clear docstrings/comments explaining what they do and how to use them.

**# NeuroCut RunPod Deployment Guide**

**## Prerequisites**
- Docker Desktop installed and running (macOS)
- Docker Hub account (free tier is fine)
- RunPod account (user already has one from earlier phases)
- HF_TOKEN environment variable set (Hugging Face access token with gated model access)

**## Step 1: Docker Hub Setup**
1. Create account at hub.docker.com if not already done
2. Run `docker login` in terminal -- enter username and password/token
3. Verify with `docker info | grep Username`

**## Step 2: Build and Push Docker Image**
1. Set environment variables:
   ```
   export DOCKER_USERNAME=your-dockerhub-username
   export HF_TOKEN=your-huggingface-token
   ```
2. Run the build script:
   ```
   chmod +x scripts/build_and_push.sh
   ./scripts/build_and_push.sh
   ```
3. Expected build time: 15-30 minutes (downloads PyTorch, TRIBE v2, etc.)
4. Expected image size: ~12-15 GB
5. Push time depends on upload speed (image is large)
6. After push, note the image URL printed by the script

**## Step 3: Create RunPod Serverless Endpoint**
Step-by-step with RunPod web console:
1. Go to runpod.io > Serverless > + New Endpoint
2. Endpoint Name: "neurocut-worker" (or any name)
3. Container Image: `your-dockerhub-username/neurocut-worker:latest`
4. GPU Configuration:
   - Select "A40" (48GB VRAM, $0.35/hr) -- validated in Phase 3
   - If A40 unavailable, use "A30" (24GB, sufficient per benchmarks showing 11GB peak VRAM)
5. Container Disk: 20 GB (for model weights cache and temp video files)
6. Environment Variables:
   - `HF_TOKEN` = your Hugging Face token (required for gated model access at runtime)
7. Advanced Settings:
   - Execution Timeout: 1200 seconds (20 minutes) -- based on benchmark data showing 10-13 min inference
   - Max Workers: 1 (for validation; increase later)
   - Min Workers (Active): 0 (scale to zero when idle -- no idle cost)
   - Idle Timeout: 5 seconds (default is fine)
   - FlashBoot: Enable if available (caches container for faster cold starts)
8. Click "Create Endpoint"
9. Note the Endpoint ID from the endpoint details page

**## Step 4: Get RunPod API Key**
1. Go to runpod.io > Settings > API Keys
2. Create new API key (or use existing one)
3. Copy the key -- it starts with "rp_"

**## Step 5: Test the Endpoint**
1. Set environment variables:
   ```
   export RUNPOD_API_KEY=your-api-key
   export RUNPOD_ENDPOINT_ID=your-endpoint-id
   ```
2. Run the test:
   ```
   python scripts/test_endpoint.py
   ```
3. Expected behavior:
   - Submits job, prints job ID
   - Polls every 30 seconds
   - First poll may show IN_QUEUE (cold start: container pulling image)
   - Then IN_PROGRESS (inference running)
   - After 10-15 minutes: COMPLETED with JSON output
   - Output saved to data/endpoint_test_result.json

**## Troubleshooting**
- "FAILED" status: Check RunPod logs (Serverless > Endpoint > Logs)
- Image pull timeout: Large image, first pull takes longer. Retry.
- OOM error: Unlikely on A40 (11GB peak vs 48GB available). If on A30 and OOM, switch to A40.
- HF_TOKEN errors: Verify token has access to meta-llama/Llama-3.2 models
- 20-min timeout hit: Video may be too long. Default limit is ~90s videos.

**## Cost Reference**
(Pull from docs/inference_benchmarks.md)
- A40: ~$0.07 per 60-second video (~12 min at $0.35/hr)
- Cold start adds ~30-60 seconds (image pull) on first request
- Scale-to-zero means zero cost when idle

**## Architecture Note**
Explain why async (/run + polling) is used instead of /runsync:
- Inference takes 10-13 minutes per 60-second video
- /runsync has a 90-second timeout -- would always fail
- /run returns immediately with a job ID
- Poll /status/{job_id} until COMPLETED or FAILED
