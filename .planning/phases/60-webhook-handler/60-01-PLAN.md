Create `web/src/app/api/stripe/webhook/route.ts` with:

1. **Signature verification** — CRITICAL: use `await req.text()` (NOT `req.json()`). Get signature from `req.headers.get('stripe-signature')`. Call `stripe.webhooks.constructEvent(body, signature, process.env.STRIPE_WEBHOOK_SECRET!)`. Return 400 on failure.

2. **Idempotency check** (per PROD-02) — Before processing, query `stripe_events` table for `event.id`. If found, return 200 immediately ("Already processed"). After successful processing, insert into `stripe_events` with `stripe_event_id`, `event_type`, `processed_at: new Date().toISOString()`.

3. **Event routing switch** — Handle these events:

   a. `checkout.session.completed`:
      - Extract `session = event.data.object as Stripe.Checkout.Session`
      - Get `user_id` from `session.metadata?.user_id`
      - Get `stripe_customer_id` from `session.customer as string`
      - Upsert into `customers` table: `{ id: user_id, stripe_customer_id }` with `onConflict: 'id'`
      - Retrieve full subscription via `stripe.subscriptions.retrieve(session.subscription as string)`
      - Call shared `upsertSubscription(subscription, user_id)` helper (defined below)

   b. `customer.subscription.created` and `customer.subscription.updated`:
      - Extract `subscription = event.data.object as Stripe.Subscription`
      - Get `user_id` from `subscription.metadata?.user_id`
      - If no `user_id` in metadata, look up from `customers` table by `stripe_customer_id = subscription.customer`
      - Call shared `upsertSubscription(subscription, user_id)`

   c. `customer.subscription.deleted`:
      - Same as above but after upsert, the status will be 'canceled' from Stripe's object

   d. `invoice.payment_failed`:
      - Extract `invoice = event.data.object as Stripe.Invoice`
      - Get `subscription_id = invoice.subscription as string`
      - Update `subscriptions` table: `.update({ status: 'past_due', updated_at: new Date().toISOString() }).eq('id', subscription_id)`

4. **Shared `upsertSubscription` helper** (file-local, not exported):

```typescript
async function upsertSubscription(subscription: Stripe.Subscription, userId: string) {
  const { error } = await supabaseAdmin
    .from('subscriptions')
    .upsert(
      {
        id: subscription.id,
        user_id: userId,
        status: subscription.status as SubscriptionStatus,
        price_id: subscription.items.data[0]?.price.id ?? null,
        quantity: subscription.items.data[0]?.quantity ?? 1,
        cancel_at_period_end: subscription.cancel_at_period_end,
        cancel_at: subscription.cancel_at
          ? new Date(subscription.cancel_at * 1000).toISOString()
          : null,
        canceled_at: subscription.canceled_at
          ? new Date(subscription.canceled_at * 1000).toISOString()
          : null,
        current_period_start: new Date(
          subscription.current_period_start * 1000
        ).toISOString(),
        current_period_end: new Date(
          subscription.current_period_end * 1000
        ).toISOString(),
        trial_start: subscription.trial_start
          ? new Date(subscription.trial_start * 1000).toISOString()
          : null,
        trial_end: subscription.trial_end
          ? new Date(subscription.trial_end * 1000).toISOString()
          : null,
        metadata: (subscription.metadata as Record<string, unknown>) ?? null,
        updated_at: new Date().toISOString(),
      },
      { onConflict: 'id' }
    )

  if (error) throw error
}
```

5. **Return 200 quickly** — Only do the critical DB write synchronously. Log errors to console.error. Return `NextResponse.json({ received: true })` for all successfully verified events (even unhandled types).

6. **Error handling** — Wrap the event processing in try/catch. On DB error, return 500 (Stripe will retry). On signature error, return 400. On unhandled event type, still return 200 (don't cause retries for events we intentionally ignore).

Do NOT: call `supabase.auth.getUser()` (webhook has no user session), use `req.json()`, import from `@/lib/supabase/server` (that's the anon client).

Create `web/src/lib/subscription.ts` with two exported functions:

1. **`getUserSubscription`** — Queries the most recent active-ish subscription for a user:

```typescript
import type { SupabaseClient } from '@supabase/supabase-js'
import type { Database, Subscription, SubscriptionStatus } from '@/lib/database.types'

/**
 * Fetch the user's current subscription. Works with any Supabase client
 * (anon for client-side reads via RLS, or admin for server-side).
 * Returns null if the user has no subscription (free tier).
 */
export async function getUserSubscription(
  supabase: SupabaseClient<Database>,
  userId: string
): Promise<Subscription | null> {
  const { data, error } = await supabase
    .from('subscriptions')
    .select('*')
    .eq('user_id', userId)
    .in('status', ['active', 'trialing', 'past_due'])
    .order('created_at', { ascending: false })
    .limit(1)
    .maybeSingle()

  if (error) {
    console.error('Failed to fetch subscription:', error)
    return null
  }

  return data
}
```

Key: Include `past_due` in the status filter so past_due subscriptions are found (not treated as "no subscription"). Accept any `SupabaseClient<Database>` so callers can pass either the anon client (for client-side reads with RLS) or the admin client (for server-side checks).

2. **`hasActiveAccess`** — Determines if a subscription grants Creator tier access (per PROD-03: past_due = grace period):

```typescript
/**
 * Check if a subscription grants Creator tier access.
 * past_due = grace period (Stripe is retrying payment, don't punish user).
 * Returns true for: active, trialing, past_due.
 * Returns false for: canceled, incomplete, unpaid, paused, null.
 */
export function hasActiveAccess(
  subscription: Subscription | null
): boolean {
  if (!subscription) return false
  const accessStatuses: SubscriptionStatus[] = ['active', 'trialing', 'past_due']
  return accessStatuses.includes(subscription.status)
}
```

3. **`getAccessLevel`** — Returns structured access info for UI display (warning banners for past_due):

```typescript
export interface AccessLevel {
  hasAccess: boolean
  tier: 'free' | 'creator'
  showWarning: boolean
  warningMessage?: string
}

export function getAccessLevel(subscription: Subscription | null): AccessLevel {
  if (!subscription) {
    return { hasAccess: false, tier: 'free', showWarning: false }
  }

  switch (subscription.status) {
    case 'active':
    case 'trialing':
      return { hasAccess: true, tier: 'creator', showWarning: false }
    case 'past_due':
      return {
        hasAccess: true,
        tier: 'creator',
        showWarning: true,
        warningMessage:
          'Your payment failed. Please update your payment method to avoid losing access.',
      }
    case 'canceled':
    case 'incomplete':
    case 'incomplete_expired':
    case 'unpaid':
    case 'paused':
    default:
      return { hasAccess: false, tier: 'free', showWarning: false }
  }
}
```

Do NOT: Import supabaseAdmin directly (let callers pass the client they need). Do NOT cache results. Do NOT add any database write operations.

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Stripe servers -> /api/stripe/webhook | Untrusted HTTP POST from the internet; must verify Stripe signature |
| webhook handler -> Supabase | Service role client bypasses RLS; must validate data before writing |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-60-01 | Spoofing | /api/stripe/webhook | mitigate | Verify webhook signature via `stripe.webhooks.constructEvent()` using STRIPE_WEBHOOK_SECRET; reject 400 on failure |
| T-60-02 | Tampering | subscription upsert | mitigate | Only write fields from Stripe event object (never from user input); use service role client with typed Database schema |
| T-60-03 | Repudiation | event processing | mitigate | Log every processed event to stripe_events table with event ID, type, and timestamp |
| T-60-04 | Information Disclosure | STRIPE_WEBHOOK_SECRET | mitigate | Env var only (no NEXT_PUBLIC_ prefix); never logged or returned in responses |
| T-60-05 | Denial of Service | /api/stripe/webhook | accept | Low risk: endpoint is lightweight (single DB upsert); Stripe rate-limits webhook delivery; Vercel handles HTTP-level DDoS |
| T-60-06 | Elevation of Privilege | supabaseAdmin misuse | mitigate | supabaseAdmin only imported in webhook route (server-only); subscription.ts accepts client as parameter to prevent accidental admin usage |
</threat_model>
