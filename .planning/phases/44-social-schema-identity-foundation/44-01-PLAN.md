Create `web/supabase/migrations/00004_create_profiles_table.sql` with the following SQL:

1. Enable citext extension: `CREATE EXTENSION IF NOT EXISTS citext;`

2. Create profiles table:
```sql
CREATE TABLE public.profiles (
  id uuid REFERENCES auth.users(id) ON DELETE CASCADE PRIMARY KEY,
  username citext UNIQUE,
  avatar_url text,
  bio text,
  created_at timestamptz DEFAULT now() NOT NULL,
  updated_at timestamptz DEFAULT now() NOT NULL,
  CONSTRAINT username_format CHECK (
    username IS NULL OR (
      length(username) BETWEEN 3 AND 20
      AND username ~ '^[a-z0-9_]+$'
    )
  )
);
```

3. Create auto-creation trigger function with SECURITY DEFINER:
```sql
CREATE OR REPLACE FUNCTION public.handle_new_user()
RETURNS trigger AS $$
BEGIN
  INSERT INTO public.profiles (id) VALUES (NEW.id);
  RETURN NEW;
END;
$$ LANGUAGE plpgsql SECURITY DEFINER;
```

4. Create trigger: `CREATE TRIGGER on_auth_user_created AFTER INSERT ON auth.users FOR EACH ROW EXECUTE FUNCTION public.handle_new_user();`

5. Reuse existing `handle_updated_at` function (from 00001 migration) for updated_at trigger on profiles:
```sql
CREATE TRIGGER on_profiles_updated
  BEFORE UPDATE ON public.profiles
  FOR EACH ROW
  EXECUTE FUNCTION public.handle_updated_at();
```

6. Enable RLS and create policies:
- `ALTER TABLE public.profiles ENABLE ROW LEVEL SECURITY;`
- SELECT policy: `USING (true)` named "Anyone can view profiles"
- UPDATE policy: `USING (auth.uid() = id)` named "Users can update own profile"

7. Backfill existing users:
```sql
INSERT INTO public.profiles (id)
SELECT id FROM auth.users
ON CONFLICT (id) DO NOTHING;
```

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-44-01 | Elevation of Privilege | handle_new_user trigger | mitigate | SECURITY DEFINER scoped to single INSERT into profiles; trigger function body contains no user-controlled input |
| T-44-02 | Tampering | profiles UPDATE RLS | mitigate | RLS policy restricts UPDATE to `auth.uid() = id` -- users can only modify their own row |
| T-44-03 | Information Disclosure | profiles SELECT policy | accept | Profiles are intentionally public (needed for /u/username pages); only username, avatar, bio exposed -- no sensitive data |
| T-44-04 | Tampering | username CHECK constraint | mitigate | Server-side CHECK constraint `'^[a-z0-9_]+$'` prevents SQL injection and enforces format regardless of client |
</threat_model>
