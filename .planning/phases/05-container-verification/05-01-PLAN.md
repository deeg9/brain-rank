Create scripts/build_and_verify.sh — a single bash script the user runs on a RunPod GPU pod after cloning the repo.

The script must do the following steps in order:

1. **Pre-flight checks:** Verify docker is available, nvidia-smi works, and HF_TOKEN env var is set. Exit with clear error if any missing.

2. **Docker build:** Run `docker build --build-arg HF_TOKEN=$HF_TOKEN -t neurocut .` with timing. Capture the exit code. If build fails, print the error and exit.

3. **Image size capture:** Run `docker images neurocut --format "{{.Size}}"` and `docker images neurocut --format "{{.Repository}}:{{.Tag}} {{.Size}} {{.ID}}"`. Print the size prominently.

4. **GPU verification:** Run `docker run --rm --gpus all neurocut python -u scripts/verify_container.py`. Capture exit code and full output. This is the CNTR-04 check — all sub-models load and torch.cuda.is_available() returns True.

5. **Model load test:** Run `docker run --rm --gpus all -e HF_TOKEN=$HF_TOKEN neurocut python -u -c "from tribev2 import TribeModel; m = TribeModel.from_pretrained('facebook/tribev2'); print('TribeModel loaded successfully'); import torch; print(f'GPU: {torch.cuda.get_device_name(0)}'); print(f'VRAM allocated: {torch.cuda.memory_allocated()/1e9:.2f} GB')"`. This tests actual model weight download and GPU loading inside the container.

6. **Summary output:** Print a structured summary block with:
   - Build time
   - Image size (from step 3)
   - Verification result (pass/fail from step 4)
   - Model load result (pass/fail from step 5)
   - Weights strategy recommendation: "Use RunPod Network Volume" with rationale (model weights are 6-11GB, baking them creates 20GB+ image, network volume eliminates cold-start downloads while keeping image lean)

Use `set -euo pipefail`. Add `#!/usr/bin/env bash` shebang. Make the script self-documenting with echo statements for each step. Use SECONDS built-in for timing.

Do NOT use `set -e` for the docker run steps — capture exit codes manually so the script can report partial results if model load fails but verification passes.

The weights strategy recommendation should be printed as part of the summary, explaining:
- Image size without weights (from step 3) vs estimated with weights (add ~8-10GB)
- RunPod Network Volume mounts at /runpod-volume, models cache to HF_HOME
- Recommendation: Set HF_HOME=/runpod-volume/huggingface in RunPod endpoint config
- First cold start downloads weights (~2-5 min), subsequent starts use cached weights

<threat_model>
## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| Host -> Container | Docker build context and runtime env vars cross into container |
| Container -> HuggingFace | HF_TOKEN sent to external API for model downloads |
| Container -> GPU | Container accesses host GPU via --gpus all |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-05-01 | Information Disclosure | scripts/build_and_verify.sh | mitigate | Script must never echo or log HF_TOKEN value. Use presence check only: `[ -n "$HF_TOKEN" ]`. Pass via --build-arg and -e flags (not command line echo). |
| T-05-02 | Elevation of Privilege | Docker --gpus all | accept | Required for GPU verification. RunPod pods are ephemeral single-tenant — acceptable risk. |
| T-05-03 | Information Disclosure | docker build layer caching | mitigate | HF_TOKEN passed as ARG (not ENV in early layers). Docker build cache on pod is ephemeral. Warn user not to push built image to public registry with baked token. |
</threat_model>
