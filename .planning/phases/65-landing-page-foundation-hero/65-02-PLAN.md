Create a new file `web/src/components/hero/BrainHero.tsx` -- a standalone decorative 3D brain canvas component. This is a simplified version of the existing BrainViewer pattern, stripped to decorative-only mode per HERO-01.

**Key differences from BrainViewer/BrainGlowMesh (DO NOT copy their data-handling logic):**
- No `vertexDataA`/`regionColors` props -- uniform monochrome material
- No `OrbitControls` -- user cannot interact (purely decorative)
- No hover/tooltip system -- no `onHoverVertex` callback
- No import of `VERTEX_COUNT` from `@/lib/vertex-codec` or `buildColormapLUT`/`applyThresholdGlow` from `@/lib/colormap`
- Auto-rotation via `useFrame` on the group ref (NOT via OrbitControls)

**Component structure:**

1. **`DecorativeBrainMesh` (internal component):**
   - Load GLB: `useGLTF('/models/brain-fsaverage5-unified.glb')` -- same model path as existing components
   - Clone geometry from `nodes.brain.geometry` (same pattern as BrainGlowMesh line 67-71)
   - Create a `Float32Array` color buffer sized to `geometry.attributes.position.count * 3`
   - Create a `BufferAttribute` with `DynamicDrawUsage` for the color buffer
   - Set the color attribute on the cloned geometry
   - **Shimmer via `useFrame`:** All vertices get a subtle white pulse (no threshold checking since there are no "active" regions). Use spatial sine waves based on vertex position for organic flow:
     ```
     const t = clock.getElapsedTime();
     for each vertex i:
       px = positions[i * 3]
       py = positions[i * 3 + 1]
       wave = sin(px * 0.05 + t * PI) * 0.5 + 0.5  // ~0.5Hz spatial wave
       emissive = 0.12 + wave * 0.06                 // range 0.12 to 0.18
       colors[i*3] = colors[i*3+1] = colors[i*3+2] = 0.2 + emissive  // grayscale 0.32 to 0.38
     colorAttr.needsUpdate = true
     ```
   - Material: `<meshStandardMaterial vertexColors toneMapped={false} roughness={0.7} metalness={0.1} emissive="#ffffff" emissiveIntensity={0.15} color="#333333" />`
   - Dispose cloned geometry on unmount (same pattern as BrainGlowMesh line 73-75)

2. **`BrainHero` (exported component):**
   - Wrapper div: `className="absolute inset-0"` with `aria-hidden="true"` (decorative, per accessibility spec)
   - WebGL context cleanup on unmount using `glRef` pattern from BrainViewer (lines 136-147):
     ```typescript
     const glRef = useRef<WebGLRenderingContext | WebGL2RenderingContext | null>(null);
     useEffect(() => {
       return () => {
         if (glRef.current) {
           const ext = glRef.current.getExtension('WEBGL_lose_context');
           ext?.loseContext();
           glRef.current = null;
         }
       };
     }, []);
     ```
   - R3F `<Canvas>` with:
     - `camera={{ position: [0, 0, 190], fov: 45 }}` -- use existing CAMERA_DISTANCE of 190 (the GLB model is in brain-scale coordinates, not unit-scale; 3.5 from UI spec assumed unit-scale but the actual model needs 190)
     - `dpr={[1, 1.5]}` -- good balance of quality vs performance
     - `style={{ background: 'transparent' }}` -- let CSS handle background color
     - `gl={{ alpha: true, antialias: true }}` -- transparent canvas, smooth edges
     - `onCreated={({ gl }) => { glRef.current = gl.getContext(); }}` -- capture context for cleanup
   - Inside Canvas, wrapped in `<Suspense fallback={null}>` (text renders immediately, brain fades in after GLB loads):
     - `<ambientLight intensity={0.3} color="#ffffff" />` -- soft ambient fill
     - `<pointLight position={[2, 3, 4]} intensity={0.8} color="#ffffff" />` -- single directional highlight (simpler than BrainViewer's 3 lights)
     - `<Center>` from drei -- centers the brain mesh
     - Inside Center: `<group ref={groupRef} rotation={[-Math.PI / 2, 0, 0]}>` -- same rotation as existing BrainViewerCanvas
     - The group ref is used for auto-rotation in a `useFrame` hook (see RotatingGroup below)
     - `<DecorativeBrainMesh />` inside the group
     - `<EffectComposer>` with `<Bloom>`:
       - `luminanceThreshold={0.6}` -- only bright spots bloom
       - `luminanceSmoothing={0.4}` -- smooth falloff
       - `intensity={1.5}` -- noticeable but not overwhelming
       - `radius={0.8}` -- medium spread
       - `mipmapBlur` -- performance-friendly blur method

3. **Auto-rotation (RotatingGroup or inline useFrame):**
   Create a small wrapper component or use a `useFrame` inside the Canvas:
   ```typescript
   function RotatingGroup({ children }: { children: React.ReactNode }) {
     const ref = useRef<THREE.Group>(null);
     useFrame((_, delta) => {
       if (ref.current) ref.current.rotation.y += delta * 0.3;
     });
     return <group ref={ref} rotation={[-Math.PI / 2, 0, 0]}>{children}</group>;
   }
   ```
   This replaces OrbitControls autoRotate -- simpler, no user interaction, constant speed.

4. **`prefers-reduced-motion` support:**
   Check `window.matchMedia('(prefers-reduced-motion: reduce)').matches` in a `useState`/`useEffect` and pass it down. If reduced motion, set rotation speed to 0 (brain is static).

5. **Module-level preload:**
   `useGLTF.preload('/models/brain-fsaverage5-unified.glb');` at the bottom of the file (same pattern as BrainGlowMesh line 210 and BrainViewerCanvas line 117).

6. **Add `'use client'` directive** at the top of the file (R3F components must be client components).

**Do NOT:**
- Import BrainGlowMesh, BrainViewerCanvas, or BrainViewer
- Import VERTEX_COUNT, buildColormapLUT, or applyThresholdGlow
- Add OrbitControls
- Add hover/tooltip handling
- Use dynamic import -- R3F Canvas handles SSR in Next.js 16
