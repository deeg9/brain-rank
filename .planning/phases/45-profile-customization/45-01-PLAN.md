## Trust Boundaries

| Boundary | Description |
|----------|-------------|
| client -> Storage API | File upload crosses from untrusted client to Supabase Storage |
| client -> Profile API | Bio/avatar_url text input from untrusted client |

## STRIDE Threat Register

| Threat ID | Category | Component | Disposition | Mitigation Plan |
|-----------|----------|-----------|-------------|-----------------|
| T-45-01 | Tampering | Avatar upload | mitigate | RLS policy restricts uploads to user's own subfolder path via `(storage.foldername(name))[1] = auth.uid()::text` |
| T-45-02 | Spoofing | Avatar upload path | mitigate | File path uses authenticated user.id, not user-supplied value; upsert=true overwrites only own file |
| T-45-03 | Info Disclosure | Avatar bucket | accept | Avatars are intentionally public (profile images); no PII beyond chosen photo |
| T-45-04 | Denial of Service | Large file upload | mitigate | Client-side 2MB file size check before upload; Supabase Storage has server-side limits |
| T-45-05 | Tampering | Bio XSS | mitigate | Bio rendered as text content in React (not dangerouslySetInnerHTML); React auto-escapes |
| T-45-06 | Tampering | Bio length bypass | mitigate | Server-side validation in PATCH /api/profile enforces bio.length <= 160 |
</threat_model>
