  <action>
Create ui-specs/gaps-responsive.md documenting how every screen adapts across breakpoints.

Start with a **Breakpoints** section defining the breakpoint system:
- **Mobile**: 320px - 767px (single column, touch-first)
- **Tablet**: 768px - 1023px (flexible columns, touch + pointer)
- **Desktop**: 1024px+ (multi-column, pointer-first) -- this is what canonical specs currently describe

Then for EACH canonical screen (Upload, Processing, Results Overview, Results Detail, Dashboard) AND each gap screen (auth, settings, billing, errors, onboarding, profile), document:

**Layout Adaptations:**
- How the sidebar nav transforms (collapses to bottom tab bar on mobile, hamburger on tablet)
- How multi-column layouts restack (e.g., Results Overview timeline + video side-by-side on desktop becomes stacked on mobile)
- How data-dense components adapt (e.g., Dashboard bento grid goes from 3-col to 2-col to 1-col)

**Component Behavior Changes:**
- Video player: full-width on mobile, constrained on desktop
- Timeline: horizontal scroll on mobile vs full-width on desktop
- MetricCards: stack vertically on mobile, grid on desktop
- DataTables: horizontal scroll or card view on mobile
- Modal dialogs: full-screen on mobile, centered overlay on desktop

**Touch Considerations:**
- Minimum tap target sizes (44px per Apple HIG)
- Swipe gestures replacing hover interactions
- Timeline scrubbing with touch vs mouse

**Navigation Changes:**
- Sidebar becomes bottom tab bar (mobile) or collapsible drawer (tablet)
- Breadcrumbs collapse to back arrow on mobile
- Action buttons move to fixed bottom bar on mobile where appropriate

Structure as H2 per section (## Breakpoints, ## Global Navigation, ## Upload, ## Processing, etc.) with consistent sub-sections for layout, components, and touch.

Include a responsive coverage matrix at top similar to Task 2's pattern showing which screens need the most adaptation work.
